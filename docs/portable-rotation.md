# 双便携版构建方案

两个完整应用目录分别是 `release/portable`（便携版）和 `release/portable2`（便携版 2）。运行中的版本继续使用自身的代码与资源，构建输出到另一个目录。

## 使用

```powershell
pnpm run build:portable
```

| 检测到的状态 | 打包目标 |
|---|---|
| portable 正在运行 | portable2 |
| portable2 正在运行 | portable |
| 两个版本均未运行 | portable |
| 两个版本均正在运行 | 停止发布，保留两个版本 |

仅指定本次目标时使用 `pnpm run build:portable --target portable2`。指定目标正在运行时，构建报错，不能强制覆盖。

原来的 `node scripts/make-desktop-bundle.mjs` 也自动选择空闲目录；已有 `BYQX_DESKTOP_BUNDLE_DIR` 指定目录能力继续保留，并增加运行检测。

## 发布流程

1. 根据 Windows 进程的实际可执行文件路径识别目录，包括后台与托盘进程。无法取得路径时，停止构建。
2. 取得构建锁，防止两次构建同时操作目录。构建 Astro 桌面产物，不执行云端数据库迁移。
3. 在隐藏暂存目录组装完整 Electron 程序、模板库和运行依赖。
4. 发布前重新检测运行状态。自动模式重新选择空闲目录；固定目标模式在目标启动后停止发布，保留暂存产物。
5. 先保留目标的旧目录，再移动新包；替换失败时恢复旧目录。发布成功后写入 `release/portable-build.json`，记录实际输出目录和入口。

构建不结束进程、不自动启动新版本。两个版本沿用 `%APPDATA%/byqx-blog-desktop` 的笔记数据库和设置。日常使用现有单实例机制，切换时保存内容并完全退出旧版本后，打开另一个目录中的 `白衣卿相.exe`。这是切换新版所需的操作，构建期间可持续学习。

搬到其他位置时保留整个目录，包括 `resources`，不能只移动 EXE。

## 验证

自动化覆盖双向目标选择、两个目录同时占用、显式目标保护、路径边界、发布前状态变化和构建锁。发行验收使用隔离配置、隔离数据库运行真实 Electron，不访问学习中的用户数据。
