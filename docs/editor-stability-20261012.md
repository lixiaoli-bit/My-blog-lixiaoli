# 单窗口版本恢复与编辑视口稳定性修复

日期：2026-10-12。用户反馈在 408 文档文章中进入编辑就提示正文冲突，滚动或收起/展开时出现跳位。

## 已复现的原因与修复

1. **已保存的旧暂存稿仍携带旧版本号。** 打开编辑器时，即使暂存正文与服务器刚读取的正文完全相同，旧逻辑仍恢复暂存稿的 `expectedContentHash`。接着输入新内容会被服务器拒绝，单个窗口也能复现。现在先核对正文，一致时清理已落盘的暂存稿并采用当前版本；真正分歧的暂存稿继续保留原基线，不自动覆盖服务器。异步计算基线也不得回退本窗口刚收到的保存版本；如果加载期间完成了本窗口的保存，会重新读取对应的正文，不将旧内容配上新版本号。后台正文保存也会失效旧文档预取，避免缓存读回本窗口自己的旧文本。
2. **折叠一个块时，全篇块的高度身份均失效。** 全局尺寸修订数让未显示的块也丢失 CodeMirror 高度估算。长文中点击可见 Callout 的“收起”，旧代码从 `scrollTop=3600` 跳到 `2482`。现在按块的源码位置记录尺寸修订，只失效发生变化的块；嵌套编辑器同时更新其外层拥有者。相同操作修复后保持 `3600`，展开/收起不改动 Markdown。

版本不一致只能说明服务器正文与当前编辑基线不同，不能证明一定存在其他窗口。保存提示改为“服务器正文版本已变化，当前改动已暂存”。保留两个便携版目录本身不会产生冲突；同时运行并写入同一数据库才可能发生真实竞争。此次只读进程检查仅发现 `portable-workspace-20261012` 的主程序运行，未操作或关闭用户客户端。
