阶段 B 后续更新：本报告保留阶段 A 的问题与原始实验结果；前三项内核问题的正式修复与验证见 [编辑内核修复与验收记录](./15-编辑内核修复与验收记录.md)。

日期：2026-10-12。阶段 A 的首轮研究交付。已开展静态调查和隔离运行时实验；本轮未修改正式编辑器实现，阶段 B 修复尚未开始。

## 1. 结论与采用方向

用户描述的块间空行点击问题已复现并定位：Callout 的块级 Widget 使用上下 `8px` 外边距，使真实 DOM 的垂直位置与 CodeMirror 的块高度模型不一致。点击源码中确实存在的空行，最终选区落到了下一个块的起点。只在研究页面临时移除这两段外边距，同一点击即落回正确的空行。

该问题在首页文章、文档文章、日历日记和速记的实际 React 消费者中均复现。分栏和折叠面板相邻空行也观察到同类点击错误。普通引用与普通嵌套引用在本次样例中正常，不能称为“所有引用语法都不可点击”。

Obsidian 对同样的普通引用、嵌套引用、Callout 和折叠 Callout 样例，在左/中/右点击测试中均正确定位。两个编辑模式与阅读模式之间切换时，它保留原编辑器对象、选区和撤销历史。项目的视觉/源码切换已经保留历史，应继续使用；文章原位编辑退出到阅读时卸载编辑器，重新进入虽保留保存后的内容，却清空撤销历史并将选区重置到开头。

采用方向：先修复共享块布局与命中，再修组合输入/Widget 提交，随后统一文章会话和标准语法识别。继续使用现有 CodeMirror 内核、项目 MDX 管线与自定义块编辑器，不整体替换为 Obsidian 的实现或普通 HTML 富文本编辑器。

## 3. Obsidian 三种模式的实现证据

### 编辑：Live Preview

Live Preview 是 CodeMirror 内的 Markdown 编辑状态，源文档仍是 Markdown，格式化由扩展和装饰控制。光标进入格式内容时相关标记可见，离开后可隐藏。[官方模式说明](https://obsidian.md/help/edit-and-read) [官方 Decoration 说明](https://docs.obsidian.md/Plugins/Editor/Decorations)

实际打包代码中，编辑组件先创建一个 CodeMirror 实例；`getDynamicExtensions()` 组合语言、主题、Live Preview、属性、用户插件等动态扩展，`updateOptions()` 向该实例发送 compartment 重配置和控制即时预览的状态效果。`toggleSource()` 修改 `sourceMode`、调用 `updateOptions()` 并派发状态效果，未在此方法重建编辑器。

运行时观察：视觉/源码往返后 EditorView 对象身份保持一致，Markdown 和选区保持一致。本次普通引用与 Callout 间的真实鼠标点击全部落在预期空行。表格单元格点击后使用独立的 CodeMirror 单元格编辑区；本次长停顿组合输入探针没有重复文本。

采用：保持项目现有 `Compartment.reconfigure`；共同的标准 Markdown 更适合基于语法树的范围识别。项目的多栏、Tabs 等自定义子编辑器有自己的价值，继续保留，不要求改成所有内容都显示原始标记。

### 源码：Source mode

Source mode 与 Live Preview 操作同一编辑组件，以动态扩展和显示状态切换，不是 Markdown↔HTML 的数据转换。

运行时样例输入“历史”后，切源码再回视觉：两边都保留文本、选区和可撤销的输入。项目此部分已经达到本轮目标，应保留；宿主按钮把焦点移走是普通 DOM 焦点行为，不应误判为文档丢失。

### 预览：Reading view

打包代码 `setMode()` 在离开编辑状态时等待保存，读取原模式的滚动/折叠信息，调用 `hide()`/`show()`，向新模式传递共享内容、滚动和折叠状态。编辑组件的 `set()` 首次初始化 EditorState，后续在内容完全相同时直接返回；内容不同时尝试缩小变更区间，而非每次全篇重建。另观察到按文件保存和恢复历史的实现片段，但本次没有验证跨文件历史缓存的全部策略。

预览 renderer 有独立的 text、sections、异步解析、虚拟显示和布局状态。`set()` 排队渲染；`parseAsync()` 向 worker 提交 section 解析，失败可走同步解析；`parseFinish()` 根据已有 section HTML 复用候选，`onResize()` 更新布局与虚拟显示。这些是源码静态观察，不意味着已经量化其性能，也不意味着 worker 执行路径在所有环境都可用。

运行时验证了同一文章的编辑→阅读→编辑：EditorView 仍存在且对象不变，选区与文本保持；返回后 Ctrl+Z 能撤销进入阅读前的最后一次输入。

采用：文章当前会话优先保留挂载的 EditorView，阅读时暂停/隐藏展示；同文章返回时复用。只在换文章或页面销毁时释放，且必须检查外部内容版本，不能以旧会话覆盖新内容。项目预览继续由 `renderMdx` 生成，其自定义语法与组件不可被 Obsidian 的 parser 取代。阅读分块/缓存优化不是本轮优先项，需性能证据才引入。

## 5. 鼠标问题的根因证据

展开 Callout 样例的根文档空行位置为 22，第二个 Callout 起点为 23。真实 DOM 空行的行盒存在，`posAtDOM()` 为 22，`coordsAtPos(22)` 给出 y=124–144；取中点 y=134 点击时，`posAtCoords()` 返回 23，根选区也为 23。第一块的上/下 margin 各 8px 未进入块本身的高度，后续块模型与真实 DOM 累积偏移。

同一文档仅在页面添加 `margin-top:0; margin-bottom:0` 并请求重新测量，命中和选区均恢复到 22。分栏也观察到移除外边距后由错误边界回到正确空行。这些干预没有改变 Markdown 或正式样式文件。

当前源码位置：

- `cm-callouts.ts` 的 block replace 及 baseTheme 中 `margin: '8px 0'`。
- `global.css` 的 `.cm-columns-widget { margin: 12px 0 }` 和 `.cm-visual-directive { margin: 1rem 0 }`。
- 已安装 `@codemirror/view` 类型说明明确要求 block-level decorations 不使用垂直外边距，高度动态变化应请求测量。该约束也适用于项目独有块，不能仅修 Callout 后结束。

推荐修法：块 Widget 的外层 margin-block 归零；用纳入测量的外层 padding 或内部布局保留原视觉留白，避免改变阅读态普通 `.callout` 样式。折叠、展开、异步内容和子编辑器高度变化触发根视图 `requestMeasure()`。不推荐给鼠标点击硬编码 y 补偿，也不推荐通过新增 Markdown 空行“修复”定位。

## 7. 下一阶段的具体修复顺序

1. **P1：块几何**。给 Callout、分栏、折叠及 Tabs 的块级外层建立无垂直 margin 的统一约束；保留可见留白和所有控件。先把本报告的错误点击写成失败回归，再改布局；动态高度刷新后重新测量。
2. **P1：表格组合输入**。记录 composition 生命周期；组合期间暂停计时提交，compositionend 后读取最终 DOM 并提交一次；不能重建正在组合输入的单元格。本轮建议先修现有 contenteditable 管线，避免为了参考 Obsidian 一次性更换表格编辑架构。
3. **P2：标准语法**。先把嵌套强调、转义、行内代码范围转交现有 CodeMirror Markdown 语法树；数学公式、项目自定义扫描器和复杂 Widget 保留。不要同时重写整个装饰系统。
4. **后续阶段 C：文章会话**。优先保留同文章 EditorView，阅读时隐藏而非销毁；恢复时校验外部版本并测量。继续保留源码 compartment 和既有滚动锚点，不新增后台覆盖路径。
5. **阶段 C/D：宿主边界**。统一预览/保存/复制/导图取源/切文章前等待输入完成；保留日记手动保存与速记自动保存的产品区别。补齐速记预览身份/序号守卫，再做真实宿主网络和冲突验收。

进入阶段 B 时，仅实现前三项已复现的内核问题；文章会话、按钮和保存宿主调整仍按原分阶段计划推进。每一项都有失败用例、根因、最小改动与保留功能验证，不以此次研究为理由重写业务层。
