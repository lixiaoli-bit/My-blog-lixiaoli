# Obsidian 逆向对比与 Markdown 编辑器修复计划

日期：2026-10-12。状态：阶段 A 首轮研究、阶段 B 内核修复已交付。研究结果见 [三模式与全入口对比研究](./14-Obsidian三模式与全入口对比研究.md)，实现与验收见 [阶段 B 修复记录](./15-编辑内核修复与验收记录.md)。阶段 C 的文章会话与宿主保存边界仍待实施。

## 1. 目标与已经确定的范围

用本机 Obsidian 1.13.7 的应用产物、官方说明和隔离运行时实验，分析 Live Preview、Source mode、Reading view 的实现与行为，再与 My-Blog 当前工作区逐项对比。采用能提高正确性与体验的机制，在项目中独立实现；保留项目已有语法、视觉风格、保存规则和业务功能。

- 覆盖所有实际使用 `MarkdownEditor` 的入口；优先处理光标与输入，再处理模式切换和渲染一致性。
- 用户提供的首要问题：两个引用块之间的空行无法用鼠标直接定位光标，需要通过上下方向键移入。阶段 A 已在 Callout 等块间复现垂直外边距导致的错位；阶段 B 已修复并验证四个实际入口。普通引用在本轮样例中原本正常。
- 普通引用、Callout 和项目自定义容器分别建模，不能将它们都视为同一种块。
- 本计划不直接修改业务代码、不部署、不更换用户正在使用的桌面程序。调查文档与证据文件可以保存。

三种模式的语义：编辑 = Live Preview，源码 = Source mode，预览 = Reading view。阅读视图不提供普通正文输入；可点击的任务、折叠等控件单独记录其是否修改内容，不笼统假定所有阅读交互都只读。两种编辑模式均操作同一 Markdown 文档。[Obsidian 官方模式说明](https://obsidian.md/help/edit-and-read)

### 项目入口与内核

| 入口/消费者 | 当前实际状态 | 本轮处理 |
| --- | --- | --- |
| `/doc/[id]` | `DocInlineEditor` 原位编辑，已有编辑/预览/源码入口 | 完整三模式、输入和保存验收 |
| `/edit/[id]` | 首页文章工作区也挂载 `DocInlineEditor`，不是旧 `LiveEditor`；当前标题入口主要为编辑切换 | 完整三模式验收；补齐与文档页一致的显式模式入口 |
| `/edit`、旧新建书签、文章管理入口 | 选择/创建文章后进入首页文章工作区 | 验证导航和创建动作不会丢失输入或误建文章 |
| 日历日记弹窗 | `CalendarDiaryDialog` 使用共用编辑器，独立保存宿主 | 光标、输入、复杂块、关闭/保存回归 |
| 全站速记浮窗 | `QuickNoteFloat` 使用共用编辑器，独立保存宿主 | 光标、输入、切换笔记、收起/关闭保存回归 |
| `LiveEditor`、`DiaryEditor` | 当前源码搜索没有找到生产页面的挂载引用 | 内核/宿主契约测试；不为测试重新挂回页面，不把它们算作已验证的生产入口 |
| 表格、Callout、选项卡/折叠/画廊、分栏内的编辑区 | 属于上述入口中的嵌套输入或子 CodeMirror | 单独记录焦点、坐标、父子内容和撤销历史 |

`MarkdownEditor` 的视觉/源码切换已经通过 `Compartment.reconfigure` 完成，不重建根编辑器；应保留此路线。原位编辑退出阅读时条件渲染会卸载编辑器；应测试重新进入时选区、历史和位置的实际丢失程度。

项目 Live Preview 使用 StateField 装饰、按不可变文档缓存、选区相关的源码回显；公式和复杂块存在 replace Widget。表格用 contenteditable 单元格和 300ms 延迟提交；Callout、分栏与可视指令内含子编辑器。因此，命中映射、延迟输入提交、父子事务和 Widget 生命周期是重点，而非单纯 CSS 外观对比。

当前编辑器与渲染器已有大量未提交修改。后续基线必须包含这些修改和新交互 HTML 功能；不得 reset、清理或覆盖它们。既有调研与定位文档是历史背景，所有“已经修好”均需在当前代码与运行时重新核实。

## 3. 阶段一：证据研究与同样例对比

### 静态调查

1. 固定安装版本、应用包摘要与项目工作区快照；复用本次部分 Evidence，保存源成员清单、路径、摘要和原始偏移。
2. 先追踪模式命令、编辑器创建/复用、`toggleSource`、Live Preview 状态、阅读渲染管线与内容更新，不再直接重复相同的整包请求。
3. 在独立调查目录读取/提取实际包内 `package.json`、`app.js` 与必要入口。REA 6.4.0 没有源路径过滤时，分析仅包含目标成员的提取目录，明确其来自原 ASAR、覆盖为局部，外部关系未解析；必要时将单源时间上限提高到 120s，并记录实际限制与结果。
4. 对超大打包文件先定位精确方法/类，再记录其调用者、状态字段和范围；截取片段只能作为局部代码观察，不能冒充完整应用图。使用 retained Evidence 的 item/page/trace；当工具不能提供语义关系时保留 unknown，并用运行时核实。
5. 为装饰范围、鼠标位置转换、组合输入、事务映射、撤销分组、表格编辑和预览增量更新分别建立问题清单；不要求恢复无关模块，也不以压缩变量名作为跨版本身份。

### 隔离运行时对比

在独立 Obsidian 用户数据目录和测试 vault 中运行安装版，使用只绑定回环地址的 CDP；先核实用户目录、vault 路径和单实例行为均隔离，再开展实验。若无法确认隔离，不对真实 vault 执行输入操作，记录这一测试限制。禁用第三方插件和自定义主题，区分核心行为与插件行为。

My-Blog 使用独立测试数据库、测试账户和临时文章/日记/速记，禁用测试环境的真实云同步。不得直接运行连接当前用户桌面数据库的旧验证脚本来修改正式数据。已有可独立运行的编辑器 fixture 优先复用。

每个场景在两边使用相同 Markdown 和操作序列，记录：源码前后差异、光标/选区、DOM 与屏幕坐标、焦点持有者、组合输入事件、撤销结果、模式及滚动锚点。真实 Windows 中文输入法单独人工验证；合成 composition 事件和直接设置 selection 不能替代真实鼠标命中或 IME 验收。

### 对比矩阵与取舍规则

每行必须包含：功能、Obsidian 行为与证据、项目行为与证据、差异、采用方案、保留项、回归测试、已观察/推断/未知标记。调查结束后先提交矩阵和已复现问题清单，再进入代码阶段。

取舍顺序：内容保真与可继续输入 > 光标/IME/撤销正确性 > 模式一致性与无跳动 > 可维护性与性能 > 外观接近程度。共同功能采用实测更稳的方案；两边同样稳定时保留现有实现，避免无收益迁移。Obsidian 特有语法但项目渲染器尚不支持的内容只作能力差异记录，不自动新增；本项目独有功能则作为保留项，不能为了接近 Obsidian 删除。

## 4. 阶段二：优先修复鼠标定位与输入

先为“引用块间空行无法点击”建立失败用例，区分普通引用、Callout、项目提示容器以及纯布局 margin。调查必须检查 replace 的实际 `from/to`、是否包含后一行换行、空行行盒高度、`posAtCoords/coordsAtPos` 结果、事件拦截和父子焦点。

修复方向由该失败用例的证据决定，但约束已经固定：

- 源码中真实存在的空行要有可命中的行盒，点击直接定位到该行；不能为修复点击而悄悄增加空行、空格或格式标记。
- 纯视觉间距没有对应源码位置时，点击定位到最近的合法块边界；不能承诺在不存在的空行输入。
- 装饰不得吞掉相邻块的可编辑分隔行；复用 Widget 后位置必须依据当前文档重新解析或映射，不能依赖过期构建位置。
- 光标移动、装饰显隐和模式切换不是内容修改，不进入文本撤销历史。组合输入期间避免重建正在输入的 DOM 或由父子同步抢走焦点。
- 保留父 Markdown 文档作为最终内容来源；子编辑器/单元格提交回根文档，并沿用根历史。不把渲染 HTML 反向转换为主文档。
- 保留现有可视化子编辑器。先修范围和事务同步，不把所有嵌套 Widget 一次性重写成另一套编辑框架。
- 标准 Markdown 的识别优先利用当前 CodeMirror Markdown 语法树；项目扩展继续使用项目扫描器。解析边界不确定时该块保留源码和可编辑入口，不能规范化或删改原文。

## 5. 阶段三：模式与入口一致性

- 文章工作区统一显式的“编辑/预览/源码”状态与按钮语义，文档和首页文章都接同一控制流程；日记与速记保留现有简洁布局，不强行新增完整三模式工具条。
- 同一文章的视觉/源码切换继续重配置同一 EditorView。阶段 A 研究后，阅读往返优先保留当前文章的 EditorView：阅读时隐藏/暂停展示，重新进入时复用选区和历史并测量；若外部内容版本变化则先处理同步，不能使用旧会话覆盖较新内容。换文章不得串用历史；页面卸载释放会话。
- 阅读预览始终使用项目的权威 `renderMdx` 管线，保持扩展组件、目录和交互 HTML 元数据；不替换成只支持 GFM 的渲染器。
- 进入预览、复制源码、导图取源、保存和切文章前，统一提交 Widget 延迟输入，再取得最新根文档。对进行中的 IME 等待 compositionend，保证末尾字符完整，不在半个组合输入中强制切换。
- 沿用项目现有保存队列与版本/冲突保护。预览请求以文档身份和内容版本/序号校验，旧响应不得覆盖新文章、新模式或较新内容。
- 继承既有标题锚点定位；无标题和块内位置纳入源码块/段落锚点映射。尊重用户手动滚动，避免后台刷新重新抢定位。
- 内核不直接调用业务 API。现有 `sourceMode`、`getSource()`、`flushInputs()` 和 `onChange/onSave` 契约保持兼容；如需等待 IME，新增可等待的输入提交接口，旧同步接口保留，宿主统一迁移等待路径。保存、渲染 API 和存储的 Markdown 格式不变。

## 6. 必须保护的现有功能

以当前语法手册、渲染器、编辑扩展、菜单和快捷键为准列完整清单，不仅以 Obsidian 支持范围为准。至少覆盖：GFM、公式、脚注、Callout/提示块、选项卡及同步 ID、折叠/手风琴、分栏、画廊、高亮、下划线、剧透/内联注释，以及 `html-interactive`。

表格原位编辑与行列操作、嵌套块编辑、任务勾选、搜索/标题折叠、自定义快捷键、右键菜单、图片粘贴/导入、源码与导图素材导出、导图/AI 取源与保存桥接、自动保存和冲突副本均进入保护矩阵。交互 HTML 的运行按钮、执行隔离和元数据不能因为编辑器修复改变。

不更换站点样式系统，不迁移文章内容，不新增双向链接等无关业务，不构建 Android。桌面验收需要时可构建候选便携包，但替换正在使用的程序必须遵守既有保存并完全退出要求。

## 7. 测试与验收

### 首要鼠标定位场景

```markdown
> 第一块引用

> 第二块引用
```

另建两个 `[!note]` Callout、空行前后各有多个块、嵌套引用、连续无空行块、文首/文尾块、公式/图片/代码/表格邻接场景。所有断言使用真实鼠标点击，不通过设置 selection 绕过命中问题。

- 有空行：单击可见空行的左侧、中间和右侧，根 selection 应落在该行；输入“定位测试”出现在两块之间，其他源码不变。
- 无空行：点击布局间距应选到合法边界，文档内容不变；用户按 Enter 后才创建新行。
- 对已有空行场景重复“点击—输入—撤销—重做”10 次，光标、内容和焦点一致；浏览器与 Windows 桌面各验证。
- 深色/浅色、100%/125% 系统缩放、短文页面滚动/长文编辑器滚动，均检查点击落点。

### 系统性回归

| 领域 | 必须覆盖与通过条件 |
| --- | --- |
| 光标/选择 | 左右/上下/Home/End、跨块拖选、Shift 选区、多光标、点击 Widget 后继续编辑；不可进入隐藏无效位置或丢失选区 |
| 输入 | 中文 IME、标点、退格/Delete、回车/列表续写、缩进、粘贴、块边界合并/拆分；无丢字、重复或异常焦点跳转 |
| 嵌套输入 | 表格、Callout、分栏和可视指令内修改后立刻切换/关闭/保存；最后一次输入进入根 Markdown |
| 三模式 | 视觉↔源码↔阅读往返不改变文档；同一文档撤销/重做连续；首帧不闪源码；丢弃过期预览响应 |
| 内容保真 | 不编辑时逐字符一致；编辑只改目标范围；扩展嵌套、未闭合语法和未知语法不被无意删改 |
| 保存/导航 | 自动保存、失败重试、切文章/日记/速记、退出、AI/导图取源；不丢待提交输入，不串会话、不覆盖冲突 |
| 位置/性能 | 已有切换锚点场景保持 3 CSS px 内的既有验收目标（边界夹位/内容变化单列）；用户滚动后不抢位置；长文输入和装饰构建不出现全文源码回退或明显退化 |
| 扩展功能 | 上述保护矩阵每项均有显示、交互、源码保存和再次打开验证；项目独有功能不能退化 |

性能记录使用同一机器、同一文档与同一操作的改动前后数据，不声称已有 Obsidian 性能优势。长文样例使用授权本地内容的隔离副本或合成文档；历史 408 文档扫描只作参考，重新核实数量和装饰失败情况。

本轮已执行基线命令：`pnpm exec vitest run tests/editor-performance.test.ts tests/cm-table.test.ts tests/markdown-columns.test.ts tests/markdown-visual-directives.test.ts`。结果：4 文件、33 测试通过；尚无上述真实鼠标/IME/Obsidian 运行时验收。

实施时先补失败回归，再作最小修复；通过对应单测、独立浏览器 fixture、隔离业务入口与 Windows Electron 验证后，运行 Astro 检查和与改动相关的 MDX/保存/交互 HTML 测试。避免直接运行会执行数据库迁移或触及云环境的通用 build 脚本；需要桌面构建时走已验证的桌面流程。
