# 文章关联思维导图开发记录

日期：2026-10-10。按批准方案实现：独立画布、一篇一图、单击选中与右侧跳转分离、AI 候选预览后追加、跟随文章权限、第一版仅新增当前文章内引用。

## 已实现的交互

- 文档文章和首页文章编辑页在“编辑”右侧增加“思维导图”。文档切换时同步当前文章节点；公开阅读页仅在有权创建或已有导图时显示入口。
- 通过独立 `/mindmaps` 窗口打开；首次原子创建根节点，已有图读取完整节点树、布局、主题和视图。旧管理编辑地址兼容跳转。
- 沿用现有暖白纸面、深色描边、橙红色、硬阴影与字体。明暗模式复用博客的主题持久化与过渡，小屏将搜索、属性、帮助、保存放入“更多”菜单。
- 常用编辑包含同级、子主题、父主题、删除、重命名、拖动、框选、方向键导航、撤销重做、折叠、关系线、边界、概要、备注、样式和搜索。支持思维导图、逻辑图、树形图、组织结构图。
- 支持 PNG、SVG、Markdown 大纲导出和完整 JSON 导入导出。导入前下载原图备份，并校验节点与引用结构；恢复主题、布局和视图。
- Callout 和普通引用块提供专用拖拽手柄与“＋导图”；整张卡片作为引用单位，文字选区引用继续可用。落在节点上添加为子节点，空白处添加为根节点子节点。
- 节点改名与 `sourceRef` 分离。跳转前检查当前来源索引，通过同源窗口通信复用文章窗口；展开详情卡片、标题折叠和所属标签页后高亮。文档地址保留册 ID 和文章参数。
- 失效或不确定的引用显示警示；警示打开对应节点的属性，可显式重新关联。不会通过相似文字静默跳转。
- 保存按窗口串行执行；暂存草稿、断网重试、版本冲突冻结、JSON 备份、另存独立副本和备份后重读均有明确入口。草稿按窗口分别保存，其他窗口草稿可导出后恢复。
- 显式保存提交尚在编辑的节点文本；关闭窗口前捕获当前树及视图，未保存时提示。网络写入失败保留草稿，重新打开可恢复。

## 缺陷修复记录

| 原问题 | 处理方式与证据 |
| --- | --- |
| 密码门禁没有覆盖关联导图 SSR / 详情 | 移除阅读页导图数据注入；统一来源权限与密码检查；详情、列表、生成和导出复核返回 `private, no-store`。接口与浏览器门禁检查通过。 |
| `para-N` 随插入内容漂移 | 建立版本化稳定块索引；唯一未变块在移动、插入和标题改名后保留 ID；修改仅在上下文唯一时续接，歧义和删除保留失效状态。 |
| 从错误的 `getData().data` 检查引用 | 从完整 `root` 树检查，包含折叠分支；修正引擎节点树与全量配置的类型声明。 |
| 自动保存和引用添加覆盖并发修改 | `revision` 加完整内容哈希 `version`，主库原子 CAS 和统一客户端队列。数字版本相同但同步内容不同也拒绝覆盖。 |
| 跨窗口拖拽依赖当前 `window` 变量 | 使用带版本的 `application/x-byqx-mindmap-reference`，核对来源、块 ID、指纹和选区；服务端重新检查来源与目标父节点。 |
| 失败静默、卸载不销毁 | 可见错误、待添加引用重试、草稿与冲突恢复；清理引擎、观察器、监听器、计时器和通信通道。 |
| 重开遗漏主题与视图 | 用完整数据恢复配置，JSON 备份包含主题和视图；明暗切换同步画布。 |
| 逐行正则把代码中的标题当章节 | 统一 `normalizeSource` 与实际 remark 解析插件生成结构索引，整块容器与渲染来源标记同源。 |
| 折叠/展开和手动保存存在时序问题 | 去除快捷键对鼠标留在 SVG 内的依赖；显式保存捕获当前编辑和树，避免读取较早的引擎变更事件。 |
| 索引镜像写回可能覆盖另一 CAS 胜者 | 镜像同样按旧数据条件写入，创建使用冲突忽略，避免重新覆盖主库较新的块索引。 |
| 关系线完成后，延迟的重叠检查读取已清空的起点 | 在插件实例化前保护其原始检查回调；取消或完成后忽略遗留检查，保留正常连接行为，并有回归测试。 |
| 重新关联只更新数据，警示图标未刷新 | 数据变更也刷新引用图标；跳过布局期间尚未创建或已移除的 SVG 节点，渲染结束后继续核对。 |

## 数据和接口

来源类型为 `{ domain: 'article' | 'doc', targetId }`，文档来源对应 `doc_nodes` 的当前文章节点。

- `mindmap_bindings`：主键为 `domain:targetId`，唯一预留来源后只物化胜出的导图 ID，防止并发首次打开生成多图。
- `source_block_indexes`：按来源保存文章内容哈希与稳定块 ID、类型、完整 Markdown、指纹、所属标题和邻接上下文。
- `mindmap_backups`：保留历史多图脱离关联前的原始记录。旧单图自动接入；旧多图由站主选主图，其他保留为独立图。
- `mindmaps.revision`：数字版本；接口 `version` 是版本号、标题和原始导图数据的 SHA-256，防止同步产生同版本不同内容后覆盖。

| 接口 | 参数与行为 |
| --- | --- |
| `GET /api/mindmaps/source?domain=&targetId=` | 返回获准访问的文章结构与已有关联图。 |
| `POST /api/mindmaps/ensure` | `{ source, primaryId? }`，获得或创建唯一关联图；多图选择状态为 409。 |
| `GET /api/mindmaps/:id` | 返回图、来源、权限、`revision` 和 `version`。独立图限文章管理者访问。 |
| `PUT /api/mindmaps/:id` | `{ revision, version, data?, title? }`；缺少新版本字段返回 428，过期返回 409，保留客户端草稿。 |
| `POST /api/mindmaps/:id/refs` | `{ source, blockId, quote?, text?, parentId?, revision, version }`；错误父节点明确拒绝，改名不改变来源。 |
| `POST /api/ai/mindmaps` | `{ mapId, revision, version, contentHash }`，仅站主；SSE 返回进度和候选，不写入已保存图。 |

## AI 行为

复用博客的 `createSiteAi / streamSiteText` 与现有设置。生成前刷新原文保存队列并记录文章、导图完整版本；使用当前 API 或订阅模型，订阅不可用时沿用现有本地运行限制与提示。设置入口仍是 `/admin/settings`。

标题建立章节层级，卡片与普通引用块保持完整。长文章按章节和上下文预算分组，单个容器超限时明确拒绝，不截断；显示处理进度，支持取消和重试。模型输出只能引用当次提供的块 ID；验证结构、深度、数量、来源和卡片覆盖，伪造 ID 或遗漏卡片会失败。

候选先预览。空图填充分支，已有图加入“AI 整理”；应用是一次插入，可整体撤销。生成期间改文要求重新生成；预览期间改图保留候选，要求核对后显式追加。真实模型响应尚未作为本轮验收证据；自动化使用受控模型替身验证协议和失败路径。

## AI 回复解析修复（2026-10-10）

用户生成导图时遇到 `Unexpected non-whitespace character after JSON at position 4749`。原解析器直接把模型整段回复交给 `JSON.parse`，只有位于回复首尾的代码围栏能被去除；完整 JSON 后附带说明文字就会失败。

现在按括号配对提取完整 JSON，识别字符串内的引号、转义和括号，兼容说明文字与代码围栏。多个 JSON 结果不自动选择；截断、错误结构和伪造块 ID 仍拒绝，并返回中文错误。生成提示词也明确要求单个完整对象。

`tests/article-mindmap.test.ts` 与 `tests/mindmap-service.test.ts` 共 39 项通过，包含第 4749 字符报错复现和流式接口回归。Astro 类型检查为 0 errors / 0 warnings，桌面构建通过。

已覆盖 `release/portable`。桌面验证脚本的 11 项检查通过、页面异常为 0：实际打包程序连接隔离本地模型，通过完整 API 验证尾随说明与代码围栏的预览、追加、来源保留、整体撤销、失败提示和重试。1,701 个载荷文件与本次构建一致；结果见 `outputs/desktop-mindmap-build/latest-review.json` 和 `json-fix-payload-verification.json`。本地模型只复现回复格式，真实订阅模型保留实际运行验收。

## 连续定位、卡片拖入与 AI 节点校验修复（2026-10-10）

本轮先在旧便携程序中复现：第一次定位后等待高亮消失，折叠同一卡片，再点原节点右侧跳转按钮，卡片没有展开，也没有再次高亮。原因是相同 URL / hash 不产生 `hashchange`，原定位逻辑只监听该事件。现在同页跳转显式调用定位，刷新高亮计时器；连续操作取消旧请求，清理通信计时器，保存失败时仍保留原窗口和修改。隔离 Electron 检查覆盖同一链接再次点击、三个往返周期、折叠卡片、隐藏标签页与窗口聚焦。

整卡手柄显示“⠿ 拖入导图”，拖动时显示卡片预览与来源描边。画布按可见 SVG 节点的视口矩形判断落点，目标节点橙色虚线高亮，提示将加入哪个节点下；空白画布追加到根节点。跨窗口传输同时提供自定义 MIME 和有版本标识的文本备用协议，不把普通文本误识别为卡片。引用仍校验当前文章、稳定块 ID、内容指纹与选区，失败保留待添加数据；改名不改变来源。

截图中的“AI 返回的导图节点格式不正确”来自节点结构校验。历史失败没有记录模型回复或具体非法字段，因此无法恢复该次究竟是哪一个字段有误。原校验还将可选字段的 `null`、80 字以上名称及超过 80 个同级节点一律拒绝。现在规范化空值，接受 512 字以内名称并按总节点数控制规模，提示词给出明确合法 JSON 示例。真正不合法的节点结构最多自动修正一次，伪造来源、多个结果和截断 JSON 仍拒绝；失败不会改动已保存导图。

用真实配置的 `gpt-5.6-luna` 订阅模型对当前文档的隔离快照诊断：42 个块分两段，包含 27 张引用卡片。初次诊断两段成功；更新提示词后的复测第二段遗漏 1 张卡片。现从可信块索引将漏卡补入“原文引用卡片（补齐）”分支，保留原生成内容、完整卡片来源，并在预览说明补齐数量。重放该次真实模型的两份回复后，27 张卡片都被覆盖。此结果属于真实模型回复及来源验证，不代表已经完成用户真实数据库中的完整 UI 生成与追加验收。

增加请求 ID、阶段、耗时、节点校验路径和补齐数量的诊断日志，不记录文章内容、模型全文或凭据。Electron 丢弃 stdout，故诊断使用 stderr；实际打包程序已验证日志进入 `%APPDATA%/byqx-blog-desktop/logs/launch.log`。四分钟超时显示明确原因，不再只提示未收到完整候选。

## 画布边界、节点右键菜单与全文 AI 结构

截图中的图形越过工具栏和底栏来自 `.map-canvas svg` 的 `overflow: visible`。现在将 SVG 绘制限制在独立画布内，整个工作区和画布使用明确的溢出边界；打开时如果保存视图把节点移出画布，自动适应可见范围，应用 AI 结果和展开分支后也重新适应。用户后续缩放和平移仍保留，图形不会覆盖顶部和底部控件。

节点右键显示“展开所有／折叠所有”，作用于该节点的完整分支；另提供“展开整张图／折叠整张图”。空白画布的菜单作用于整张图。菜单保留纸面、深色描边、橙色硬阴影；支持方向键、Home/End、Enter、Escape、外部点击关闭及小屏边缘避让。访客可折叠查看，数据仍只读；保存冲突期间禁用操作。

重复章节的原因是将每个分段模型返回的完整树直接并列追加。新增 `mindmap-structure.ts` 使用同一份文章块索引先建立全文标题树：按标题级别和稳定块 ID 确定父子关系，每个原文标题只创建一次。每段模型都收到完整目录、所属章节 ID 和本段完整正文，先分析层级，再提炼概念与卡片。服务器把模型概念归回实际来源章节，合并同一来源卡片及重复概念，消除重复文章／章节包装和已空的跨章节包装。原文中不同位置的同名标题、同名卡片保留各自身份；没有标题的文章也能生成概念。漏卡直接补到所属章节，预览显示补齐数量。

预览增加“替换当前导图（备份）”，用于整理先前生成的错误导图。操作检查文章内容与导图版本，先触发 JSON 备份，再以一次历史操作替换根节点下的内容；根节点、主题和布局保留，可整体撤销。默认仍为“作为新分支加入”。预览期间修改导图会提示重新核对；重新生成清理上次候选，失败不显示过期结果。没有自动修改用户已保存的原图。

## 2026-10-11：节点名称 Markdown
