# 文章交互与 Markdown 桌面导出

日期：2026-10-12。范围包含首页文章、文档三模式、管理授权弹窗及 Windows Markdown 导出。动态标签保留原有组合筛选，未修改。

## 1 已实现的行为

| 入口 | 行为 |
| --- | --- |
| 文档与首页文章编辑页 | 标题按钮和右键“切换视图”共用预览、编辑、源码控制；正文、嵌套编辑块、表格与选词 AI 菜单保留各自操作 |
| 首页文章列表 | 有图左图右文，无图扩展正文；封面加载失败按无图处理；管理员右键编辑或确认删除 |
| 首页文章详情 | 阅读页、编辑页显示相同真实封面，设置或 AI 应用封面后更新编辑页展示 |
| 本册目录 | ↗ 手柄专门用于原生拖出 Markdown；原文章行的拖动排序不变；点击手柄或菜单可下载 |
| 管理授权弹窗 | 导航前关闭并取消身份查询，返回页面和迟到响应不会恢复旧弹窗 |

读取失败不挂载空的可保存编辑器，也不隐藏已有阅读正文。返回预览、重试读取和切换源码均有明确路径。源码模式无需先成功加载可视模块，支持自动保存、Ctrl/Cmd-S 及“保存源码”按钮；手动保存后保留源码视图。保存失败保留暂存稿，并区分网络、超时、HTTP 错误、登录失效和正文版本冲突。

## 2 高数文章核对

干净隔离状态下，原便携包和此前编辑器包均能打开该文章，未复现用户会话里仅显示“保存失败”的最初原因。已确认并修复的独立缺陷是：预览按钮只检查正常编辑态，无法退出读取失败状态；源码打开也依赖可视模块。保存失败的原因现在会直接显示，避免继续以同一泛化提示掩盖实际错误。

## 3 原生导出边界

渲染进程只传文章标识并接收短期令牌。主进程校验本地窗口、文档页面和文档管理权限，从现有导出端点生成临时 UTF-8 `.md`，调用 Electron `webContents.startDrag`。渲染进程无法指定任意文件路径，窗口或页面改变、令牌过期后不能启动旧导出。

当前文章先成功保存，再准备导出。首次准备尚未完成时取消本次拖动并提示稍后重试，避免导出旧内容。临时文件保留到进程退出，兼容取消和重拖；退出清理仅处理本桥接创建的文件。

## 4 验证与使用

验证脚本均使用隔离配置、数据库和回环服务，未操作真实文章库或真实云端。正文样本及失败截图、报告保存在忽略的 `outputs` 和 `.diag` 中，不进入 Git。

源码回归：100 个测试文件、1,173 项通过；Astro 检查 0 错误、0 警告，另有 51 个 hints。编辑内核浏览器回归 37 项、AI 随机封面浏览器回归 7 项通过。文章交互 Electron 回归包含三种源码保存、完整正文、故障恢复、冲突暂存、封面混排、编辑/删除权限和管理弹窗，共 20 项通过；包内编辑器回归另有 6 项通过。包内编辑器的合成 IME 检查须独立运行，避免与其他原生窗口输入或系统拖动循环交错。

隐藏窗口中 Chromium 会跳过原生转场，Astro 的动画 Promise 曾产生 `Transition was skipped`；后台文章验证显式采用其导航降级路径，不改动实际应用的动画行为。

原生 `webContents.startDrag` 及其取消路径已实际调用验证；默认回归拦截系统拖动循环，只断言真实 IPC 到原生接口的文件、图标参数。附加 `--native-drag` 可进入 Windows 系统拖动循环，取消辅助脚本只向该隔离测试进程的窗口投递 Esc/取消消息。
