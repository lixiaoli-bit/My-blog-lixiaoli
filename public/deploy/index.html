先理解架构

三种服务，各司其职。

这里的“云端部署”是把持久数据保存到云端，并让 Web 服务可以访问它们。数据库并不运行在 Vercel 函数的本地磁盘上。默认方案为 Vercel + Neon PostgreSQL；有图片上传需求时，再接 R2 或 GitHub 图床。

这套项目的数据放在哪里
组件保存或运行什么何时需要
桌面 SQLite本地文章、设置、同步记录桌面端自动创建，无需云账号
VercelAstro Web、页面、API网上浏览自己的博客
PostgreSQL 主库文章正文、设置、图片元数据Web 与桌面云同步必选
PostgreSQL 备库应用层镜像与故障切换端点可选，不等同定时备份
R2 或 GitHub 图床图片文件本地图片上传时二选一，亦可同时配置
R2 是对象存储，不是 SQL 数据库。

不开启 GitHub 图床时，上传图片使用 R2；文章与设置仍存 PostgreSQL。两种图片存储都不配置，可以写文字、引用已有的图片 URL，但不能上传本地图片。

依据：项目 db/dialect.ts、src/lib/images.ts、src/pages/api/images.ts；Vercel PostgreSQL 文档。

桌面端

先安装，直接在本地写作。

新版首次打开会生成本地配置与 SQLite 数据库，随后提供“本地使用”和“查看云端部署教程”两个入口。选择云端教程也会保留本地数据库，云端配置可以稍后完成。

  1. 获取桌面包

    使用项目提供的 Windows 安装包，或完整的便携包目录。便携版入口是 白衣卿相.exe，必须连同 resources 保留，不要单独移动 EXE。

    仓库暂不承诺固定下载文件名或每个版本都有 Release。现有下载以 项目 Releases 实际内容为准；没有对应包时，可按下方源码构建。

  2. 打开应用，选择“本地使用”

    程序默认只监听 127.0.0.1。本地数据目录为 %APPDATA%\byqx-blog-desktop，包含 config.json 与 blog-local.db。首次生成的密码与签名密钥为随机值，新安装的桌面窗口自动建立本地站主会话。

    应看到：首页可以打开，设置与写作入口可用；无需填写云端连接串。

  3. 先建立一篇测试文章

    新建并输入文字，等待保存完成，完全退出应用（含托盘）再打开。内容应仍然存在。此时“云端未配置”是正常状态，不影响本地文章保存。

开发者：从源码构建 Windows 包

安装 Node.js 24 LTS 与项目声明的 pnpm。下面命令在仓库根目录执行；不要在正在使用的便携目录内构建或覆盖程序。

npm install -g pnpm@11.20.0
pnpm install --frozen-lockfile
pnpm run build:portable --target portable-deploy-20261013

产物为 release/portable-deploy-20261013/。需要 NSIS 安装包时运行 pnpm run dist:desktop，输出位置由 desktop-builder.yml 决定。

旧版本配置会保留。

升级不会自动更改已有密码、启用自动登录或删除原文章。若旧版仍提示必须先填云端连接，请确认启动的是包含此次适配改动的新包。

桌面端 · 可选云端

连接的是数据库，不是网站网址。

先按 Web 部署 完成 Fork、创建 PostgreSQL 和首次 Vercel 构建。首次构建会初始化云端表结构，再回来配置桌面端。Vercel 项目本身并不会替你保存数据库连接到桌面设备。

  1. 打开“设置 → 云端同步”

    也可以点击该分区的“云端部署教程”回到这里。只需要桌面端同步、暂不公开 Web 时，也可以在自己电脑上按 仅初始化云数据库 的方式建表。

  2. 填写主库连接串

    使用 Neon 控制台提供的 postgresql://... 连接串，与 Web 的 DATABASE_URL 指向同一主库。备库可以留空。点击“保存连接”，保存后立即生效，无需重启。

    桌面配置字段对应 SYNC_DATABASE_URL 与可选 SYNC_DATABASE_URL_FALLBACK。桌面运行时的 DATABASE_URL 始终指向本地 SQLite，不要将它改成云库。

  3. 先测试，再同步

    点击“测试主备库连接”。主库应成功；未配置备库时允许跳过。测试仅验证数据库连通性，不代表全部表已就绪。再点“立即同步”，查看启动、读取/写入阶段、等待时长、每张表的报告与错误。

    首次同步会双向合并本地与云端记录，冲突会保存副本。建议第一次用测试文章验收，并在正式同步前保留数据库备份。没有更改时，推送/拉取计数为 0 是正常结果。

  4. 确认 Web 与桌面互相可见

    桌面新增测试文章 → 同步 → 浏览器刷新查看；浏览器修改同一测试文章 → 桌面立即同步 → 重开文章检查。两方向都通过，才说明这台设备的同步可用。

桌面端如何配置 R2？

当前 R2 凭据通过本地 config.json 配置，设置页面只管理数据库连接与 GitHub 图床。完全退出程序与托盘后，向现有 JSON 添加 R2 节 列出的字段，保留其余配置，保存后重新打开。不要把 Vercel 上的环境变量误认为会自动传到桌面。

两端应使用同一个 R2 桶与公开地址。仅同步数据库不会复制另一个桶里的图片文件，也不会把电脑上的文件自动变成公网 URL。

Web 部署

从 Fork 开始，部署到 Vercel。

这条路径将当前 Astro SSR 项目部署成 Web 服务，然后连接云数据库。它不是把你的桌面 EXE 上传到 Vercel。准备 GitHub、Vercel 与 Neon 账号；需要上传图片时，再准备 Cloudflare 或 GitHub 图床。

  1. Fork 源码到自己的账号

    打开 shijing-lu/My-blog → Fork → 选择自己的 Owner → Create fork。之后的部署应选自己的 Fork，避免误部署其他人的仓库。当前源码主分支为 master；如果你改了默认分支，以自己的仓库为准。

    GitHub Fork 复制代码，不复制作者的数据库、Vercel 项目、域名或密钥。不要提交 .env、config.json、数据库文件或带凭据的截图。

  2. 在 Vercel 导入自己的 Fork

    登录 Vercel New Project，通过 Import Git Repository 连接 GitHub。授权该 Fork 的访问权限，选中它并点击 Import。Framework Preset 选择 Astro，Root Directory 选仓库根目录。

    先完成下面的数据库和环境变量配置再点击 Deploy。若已经先触发了空配置构建，它会失败，这是保护机制；补齐配置后 Redeploy 即可。

参考：GitHub Fork、Astro on Vercel。项目已配置 @astrojs/vercel，无需再运行 astro add vercel。

必选 · PostgreSQL

创建真正持久的主数据库。

  1. 在 Neon 创建项目

    进入 Neon Console → New Project，设置名称和区域，创建数据库。区域尽量靠近你的 Vercel 函数区域。记住实际选择的 branch、database 和 role，后续桌面与 Web 必须连接相同的数据集。

  2. 复制 PostgreSQL 连接串

    使用项目的 Connect 对话框，选定 branch/database/role，开启 connection pooling，复制完整连接串。Neon 的池化主机名通常含 -pooler，保留控制台提供的 TLS 参数。不要复制 psql 命令外层，也不要添加引号。

    postgresql://USER:PASSWORD@HOST-pooler.REGION.aws.neon.tech/DB?sslmode=require

    这里全是占位符，不能直接使用。使用服务商生成的原始连接串，避免手动拼接时漏掉密码特殊字符的 URL 编码。

  3. 将它加入 Vercel 的 DATABASE_URL

    本项目读取的是 DATABASE_URL。如果使用 Vercel Marketplace 的 Neon 集成，仍要检查最终变量名；只有 POSTGRES_URL 或其他前缀变量时，需要将正确值映射到 DATABASE_URL。项目使用 postgres.js，不要求改用 Neon 专属客户端。

主数据库必须配置；备数据库可留空。

Vercel 的 SQLite 文件不适合这套云端持久化流程。本项目在 Vercel 构建时会拒绝缺少 PostgreSQL 的配置，不会静默创建一个临时数据库。

只要桌面云同步，暂不部署公开 Web

仍需要创建 PostgreSQL 并初始化表。在源码根目录安装依赖后，通过终端环境变量传入连接串，再运行迁移脚本。Windows PowerShell 示例：

$env:DATABASE_URL = '从 Neon 复制的完整连接串'
$env:DATABASE_URL_FALLBACK = ''
node scripts/migrate-deployment-schema.mjs
Remove-Item Env:DATABASE_URL
Remove-Item Env:DATABASE_URL_FALLBACK

终端历史会保存你键入的命令，注意不要分享历史或截图。脚本读取进程环境变量，不会自动读取 .env。完成后可回到桌面保存连接并同步；此路径不会生成公开网站。

参考：Neon 官方连接说明、Vercel 数据库集成。

Web · 可选自定义域名

让自己的域名指向博客。

  1. 先确认 vercel.app 地址可用

    数据库、登录和文章保存应先通过检查。自定义域名是访问入口，不会修复数据库连接或构建错误。

  2. 添加域名

    Vercel 项目 → Settings → Domains → Add Domain，填写自己拥有的域名，例如 blog.example.com。根域名与 www 的跳转方向按你需要选择。

  3. 照当前面板填写 DNS

    进入域名 DNS 服务商的管理页面，添加 Vercel 当前显示的记录。根域名通常使用 A，子域名通常使用 CNAME；验证所有权时可能还需 TXT。记录值以你项目的面板为准，本教程不写死 IP 或 CNAME 目标。

    只处理与这个博客主机名冲突的记录，不要删除邮件 MX、其他服务的 TXT 或整个 DNS 区域。使用 Cloudflare DNS 时，先按 Vercel 指引完成验证；排障时可将该主机名设为 DNS only，先验证源站路径。

  4. 等待验证与 HTTPS

    待 Vercel 显示配置有效，确认浏览器通过 HTTPS 打开成功，再将 PUBLIC_SITE_URL 更新为正式域名并 Redeploy。之后教程地址是 https://你的域名/deploy/，桌面同步仍使用 PostgreSQL 连接串。

可选 GitHub 登录如何跟随域名？

GitHub Settings → Developer settings → OAuth Apps → New OAuth App。Homepage URL 填正式网站地址，Authorization callback URL 填 https://你的域名/api/auth/github/callback。Vercel 添加 GITHUB_CLIENT_ID、GITHUB_CLIENT_SECRET，需要 GitHub 管理登录时再填写 ADMIN_GITHUB_LOGIN 白名单，重新部署后验证。普通密码登录不要求 OAuth。

参考：Vercel 域名配置。

图片存储 · 默认路径

配置 Cloudflare R2。

  1. 开通 R2，创建 Standard 桶

    登录 Cloudflare → R2 Object Storage。按账户实际提示开通（可能需要付款资料），再 Create bucket，名称例如 my-blog-media，本教程采用 Standard。查看当前额度和费用，不将开通步骤视为无限免费承诺。

  2. 生成 S3 凭据

    R2 管理页面进入 API token 管理，创建 token，选择 Object Read & Write，使用 Apply to specific buckets only 限定为该桶。保存生成的 Access Key ID 与 Secret Access Key。项目需要这两个 S3 凭据，不是将普通 Cloudflare Bearer API Token 填入 Secret 字段。

    从控制台记录 Account ID 和 S3 endpoint。通常为 https://<ACCOUNT_ID>.r2.cloudflarestorage.com；如面板为受管区域提供不同端点，完整复制它到 R2_S3_ENDPOINT。

  3. 配置公开读取地址

    生产推荐在桶 Settings → Custom Domains → Connect Domain 中连接 Cloudflare 同账户内管理的子域名，例如 media.example.com，按面板确认记录并等待可用。网站域名可以仍部署在 Vercel；图片子域名单独指向 R2。

    暂时没有域名时，可以在 Public Development URL 中启用 r2.dev 测试地址。它有访问限制，官方不建议用作生产。S3 endpoint 用于鉴权上传，不能充当公开图片地址。

  4. 在 Vercel 添加 R2 变量

    项目读取的 R2 字段
    R2_ACCOUNT_IDCloudflare Account ID
    R2_ACCESS_KEY_IDS3 Access Key ID
    R2_SECRET_ACCESS_KEYS3 Secret Access Key
    R2_BUCKET桶名，如 my-blog-media
    R2_PUBLIC_BASE_URLhttps://media.example.com，或用于测试的 r2.dev 地址
    R2_S3_ENDPOINT可选；标准端点可由 Account ID 推导，特殊端点须填

    公开地址只填基础地址，不追加桶名、/images 或对象 key。更新变量后 Redeploy。桌面端需要在自己的 config.json 添加同名字段并完全重启；数据库同步不会自动下发这些本地凭据。

  5. 上传一张小图片进行验收

    关闭 GitHub 图床开关，进入文章编辑页 → “上传封面”，选择 PNG/JPEG/WebP/GIF 图片，建议测试文件小于 1MB。检查封面显示、刷新后仍存在、Web 与桌面可打开同一图片。

    当前封面入口限制为 3MB，以避免 JSON base64 请求体超过平台限制；其他上传入口仍应按接口与平台实际限制使用。项目由服务器上传到 R2，这条路径无需浏览器直接访问 S3，也不要求为了上传而开放桶的浏览器写入 CORS。

参考：R2 S3 凭据与端点、公开桶与自定义域名。本项目采用 region=auto、S3 路径式请求。

图片存储 · 可选图床

使用独立 GitHub 仓库存图片。

  1. 创建自己的 public 图片仓库

    GitHub → New repository，例如 blog-images，选择 Public，并勾选 Add a README file，以建立真实的默认分支。不要把图片放进博客源码仓库；记住 owner、repo 和实际分支名（常见为 main）。

  2. 创建最小权限 token

    GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。Resource owner 选该仓库的属主；Repository access 选 Only select repositories，且只选图片仓库；Repository permissions 的 Contents 设置为 Read and write。设定合适有效期，保存生成的 token。

    本项目按这个 token 上传仓库文件。GitHub OAuth App 的 Client Secret 不适用于图床。组织仓库可能需要组织审批；为了减少部署步骤，个人博客优先使用自己拥有的仓库。

  3. 在博客设置中保存

    以管理身份进入“设置 → GitHub 图床”，启用图床，填 Owner、Repo、Branch 与 Token，保存后点击“测试连接”。测试成功后，在文章编辑页上传一张小图片，并确认图片仓库 img/年/月/ 目录出现新文件。

    token 保存在博客数据库，前端只读取已配置状态；留空保存表示不修改原 token。桌面与 Web 首次仍应分别确认图床状态，或通过完整数据库同步后再验证。保护数据库备份，因为其中可能含服务凭据。

  4. 验证图片在两端显示

    Web 端通过本站 /img/... 路径读取，桌面端使用 jsDelivr 直链。上传成功但显示失败时，要分别检查 GitHub 原文件、Web 回源、桌面 CDN 网络与缓存；不能把仓库提交成功等同于所有地区都能访问。

两种存储同时配置时，开启且完整的 GitHub 图床优先；图床上传失败会尝试 R2。若想固定使用 R2，将图床开关关闭。

参考：GitHub Fine-grained PAT。实际上传路径见项目 src/lib/gh-image-bed.ts。

可选 · 备数据库

先用一个主库，再考虑备库。

不需要备库时，Vercel 不添加 DATABASE_URL_FALLBACK，桌面备库输入框留空。要移除已有桌面备库，勾选“移除已有备库连接”再保存；仅留空会保留原值。

  1. 创建独立 PostgreSQL 端点

    可以使用另一 Neon 数据库或其他兼容 PostgreSQL 服务商。选择其适合 Node/Serverless 的池化连接方式，并保留 TLS 参数。不要把同一个连接串填两遍当作备库。

  2. 添加 Web 和桌面对应变量

    Web 使用 DATABASE_URL_FALLBACK，桌面使用 SYNC_DATABASE_URL_FALLBACK。Web 构建会升级并检查两端的表结构。新建博客应在正式写作前配置两端；已有主库接入空备库时，应先备份并补齐历史数据，避免故障切换后看起来“文章全没了”。

  3. 不要把镜像当成灾备快照

    项目提供应用层镜像写入和查询故障切换；不是数据库服务商保证的同步复制。写入失败、端点故障、误删和业务路径遗漏都需要单独验证。定期导出数据库或使用服务商备份能力，确认能恢复到所需时间点。

主备一致性检查与历史数据同步工具在 scripts/sync-databases.mts。执行会改数据的同步前，先运行默认只读预览、核对方向与冲突，再按工具说明决定是否应用。不要在正式库上随意断网或删除数据做测试。

常见问题

先确定故障发生在哪一层。

构建提示需要 PostgreSQL DATABASE_URL

检查变量是否在本次部署环境中存在、是否选了正确的 Production/Preview、是否以 postgres:// 或 postgresql:// 开头。保存后重新部署。不要填数据库控制台网址或 file:...。

pnpm 版本、lockfile 或 Corepack 报错

确认 Node.js 24.x、ENABLE_EXPERIMENTAL_COREPACK=1 和仓库 packageManager 一致。保留 pnpm-lock.yaml。不要通过去掉 frozen-lockfile 掩盖本地与云端的依赖漂移，先修正仓库依赖与锁文件。

数据库连接成功，但迁移或同步失败

连接探测只执行简单查询；它不检查业务表、全部写权限或主备一致性。查看构建 migration/cloud-db-check 日志，确认初始化覆盖所有表，角色有 DDL/CRUD 权限。桌面看每表同步报告，不只看“连接成功”。

点击立即同步却没有变化

新版应立即显示启动反馈与等待时长。长时间等待要看当前表、阶段和错误；所有推送拉取均为 0 可能只是没有变更。完全退出旧程序与托盘，确认启动新包。连接串调整后先测试，勿反复启动同步或把失败当成功。

R2 上传成功，图片打不开

检查 R2_PUBLIC_BASE_URL 是否是已启用的公开地址，是否误用了 S3 endpoint 或追加桶名。打开同一对象的公网 URL，检查域名有效性和公开访问状态。若修改了基础地址，旧数据库记录仍可能保存旧 URL，不会自动重写所有历史图片地址。

GitHub 图床上传失败或成功但不显示

检查 public 仓库、已存在的 branch、Contents 写权限、token 有效期与组织审批。上传失败且没有 R2 时会报最终错误。原图已在仓库但桌面不可见时，再检查 CDN 网络与缓存。

换域名后 GitHub 登录失败或分享链接还是旧域名

更新 PUBLIC_SITE_URL 并 Redeploy；使用 OAuth 时同步更新其 callback URL。AUTH_SECRET 更换会使旧会话失效，需要重新登录。数据库连接串无需因为换网站域名而修改。

可选评论、网盘与大字体上传

它们不是部署博客的前提。Twikoo 另行部署并填写 PUBLIC_TWIKOO_ENV_ID；网盘在设置中按支持的服务配置；大字体上传使用 Vercel Blob，需对应 BLOB_READ_WRITE_TOKEN。未配置时不要将这些独立功能的失败判断成主博客部署失败。
